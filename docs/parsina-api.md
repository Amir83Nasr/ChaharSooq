# مستندات API پارسینا

> رونوشت Markdown از [قرارداد اصلی پارسینا](parsina-api.pdf). منبع معتبر قرارداد، فایل PDF است. مثال‌های تصویری (تصاویر صفحه (اسکرین‌شات‌ها)) در این رونوشت آورده نشدهاند.

> **نکته پروژه (از متن قرارداد نیست):** تمام مبالغ پولی برگردانده‌شده توسط پارسینا به **ریال**
> هستند؛ چهارسوق آن‌ها را با تقسیم بر ۱۰ به تومان تبدیل می‌کند و در تمام محاسبات، ذخیره‌سازی،
> خروجی API و نمایش فقط از تومان استفاده می‌کند. فیلدهای `discount` و `extra` درخواست کالا
> **درصد**اند، نه مبلغ، و نباید تبدیل شوند. تبدیل در `backend/api/app/services/sync.py`
> (قیمت‌های کاتالوگ) و `backend/api/app/services/cardex.py` (مبالغ سطر فاکتور) انجام می‌شود.

- **نگارنده:** شرکت پارسینا پردازان آریا
- **نسخه مستند:** Parsina.win.1.0.0
- **آدرس اصلی API:** `http://IpAddress:port/Api/V1` (نسخه V1)

## تعاریف اولیه

تمامی وب‌سرویس‌های توضیح داده شده در این مستندات به‌صورت RESTful هستند و طبق همین چارچوب باید با آن‌ها ارتباط برقرار کرد.

BaseUrl در این سند معادل http://IpAddress:port/Api/V1 است.

انواع خروجی API:

نتایج انجام هر یک از عملیات می‌تواند یکی از موارد زیر باشد:

| پارامتر    | نوع داده               | توضیحات                                                                                                     |
| ---------- | ---------------------- | ----------------------------------------------------------------------------------------------------------- |
| isSuccess  | Boolean                | موفق یا ناموفق بودن عملیات که با مقدار true یا false نمایش داده می‌شود.                                     |
| statusCode | string                 | وضعیت درخواست: Success, ServerError ,BadRequest ,NotFound, ListEmpty , LogicError ,UnAuthorized , NoAccess, |
| message    | String nullable: true  | پیام فارسی عملیات.                                                                                          |
| data       | Object nullable: true  | مقدار خروجی درخواست                                                                                         |
| total      | integer nullable: true | تعداد سطرهای خروجی                                                                                          |

- مقدار خروجی درخواست‌ها در فیلدdata قرار می‌گیرد

کدهای خروجی معمول پس از انجام عملیات:

| کد  | عنوان        | توضیحات                                | مثال                                         |
| --- | ------------ | -------------------------------------- | -------------------------------------------- |
| 400 | Bad Request  | وارد کردن مقدار نادرست                 | وارد کردن مقدار صفر برای قیمت کالا در فاکتور |
| 401 | Unauthorized | عدم دسترسی                             | عدم ارسال توکن یا توکن منقضی شده             |
| 403 | Forbidden    | عدم دسترسی                             |                                              |
| 404 | Not Found    | وارد کردن مقدار ناموجود در پایگاه داده | عدم وجود شخص با شناسه وارد شده               |
| 409 | Conflict     | وارد کردن مقدار تکراری                 | ثبت کد تکراری جهت ثبت کالا                   |
| 200 | OK           | انجام عملیات بدون خطا                  | -                                            |

<a id="sec-003"></a>

## احراز هویت

جهت احراز هویت می‌توانید با استفاده از متد {{baseUrl}}/Account یک توکن JWT جهت احراز هویت کاربر ایجاد کنید که به مدت ۲ ساعت معتبر است و جهت فراخوانی تمامی متدها باید هدر Authorization استفاده شود. روش Autorization Header استفاده از هدرAuthorization همراه باطرح احراز هویت Bearer است. بعد از Bearer پس از یک فاصله، مقدار access_token قرار می‌گیرد.

Authorization: Bearer Token

## متدهای فراخوانی / اطلاعات Get

<a id="sec-005"></a>

### اطلاعات سازمان

`GET {{baseUrl}}/Account/Organizations`

**شرح:** جهت دریافت توکن نیاز به ارسال شناسه سازمان به عنوان پارامتر ورودی متد احراز هویت است، لیست سازمان ها از طریق این متد می‌توانید مشاهده و استفاده نمایید. جهت استفاده از این متد نیازی به ارسال توکن در سرآیند درخواست ناست

<a id="sec-006"></a>

### سال‌های مالی یک سازمان

| پارامتر        | نوع داده | نوع ورودی | توضیحات                                   |
