## تعاریف اولیه

تمامی وب سرویس های توضیح داده شده در این مستندات به صورت Restfull هستند و طبق همین چهارچوب باید با آنها ارتباط برقرار کرد.

BaseUrlدر این سند معادل http://IpAddress:port/Api/V1 می باشد.

انواع خروجیAPI:

نتایج انجام هر یک از عملیات میتواند یکی از موارد زیر باشد:

| پارامتر    | نوع داده               | توضیحات                                                                                                      |
| ---------- | ---------------------- | ------------------------------------------------------------------------------------------------------------ |
| isSuccess  | Boolean                | موفق یا ناموفق بودن عملیات که با مقدارtrue یاfalse نمایش داده میشود.                                         |
| statusCode | string                 | وضعیت درخواست : Success, ServerError ,BadRequest ,NotFound, ListEmpty , LogicError ,UnAuthorized , NoAccess, |
| message    | String nullable: true  | پیغام فارسی عملیات.                                                                                          |
| data       | Object nullable: true  | مقدار خروجی درخواست                                                                                          |
| total      | integer nullable: true | تعداد سطرهای خروجی                                                                                           |

- مقدار خروجی درخواستها در فیلدdata قرار میگیرد

کد های خروجی معمول پس از انجام عملیات:

| کد  | عنوان        | توضیحات                           | مثال                                         |
| --- | ------------ | --------------------------------- | -------------------------------------------- |
| 400 | Bad Request  | وارد کردن مقدار نادرست            | وارد کردن مقدار صفر برای قیمت کاال در فاکتور |
| 401 | Unauthorized | عدم دسترسی                        | عدم ارسال توکن یا توکن منقضی شده             |
| 403 | Forbidden    | عدم دسترسی                        |                                              |
| 404 | Not Found    | وارد کردن مقدار ناموجوددر دیتابیس | عدم وجود شخص با آی دی وارد شده               |
| 409 | Conflict     | وارد کردن مقدار تکراری            | ثبت کد تکراری جهت ثبت کاال                   |
| 200 | OK           | انجام عملیات بدون خطا             | -                                            |

## احراز هویت

جهت احراز هویت میتوانید با استفاده از متد {{baseUrl}}/Account یک توکنJWT جهت احراز هویت کاربر ایجاد کنید که به مدت2 ساعت معتبر می باشد و جهت فراخوانی تمامی متدها باید Authorization Header استفاده شود. روش Autorization Header استفاده از هدرAuthorization همراه باBearer Authentication scheme می باشد. بعد از Bearer با یک فاصله مقدار access_token قرار میگیرد.

Authorization: Bearer Token

### اطالعات سازمان

`GET {{baseUrl}}/Account/Organizations`

**شرح:** جهت دریافت توکن نیاز به ارسال آی دی سازمان به عنوان پارامتر ورودی متد احراز هویت است، لیست سازمان ها از طریق این متد میتوانید مشاهده و استفاده نمایید. جهت استفاده از این متد نیازی به ارسال توکن در هدر درخواست نمی باشد

<a id="sec-006"></a>

### سال های مالی یک سازمان

| پارامتر        | نوع داده | نوع ورودی | توضیحات                                   |

`GET {{baseUrl}}/BaseInfo/VoucherTypes`

`GET {{baseUrl}}/WhrsDraft/{id:int}`

**شرح:**

**پارامترهای ورودی**

| پارامتر | نوع داده | نوع پارامتر          | توضیحات |
| ------- | -------- | -------------------- | ------- |
| id      | int      | Header / querystring |         |

**پارامترهای خروجی:**

پارامترهای خروجی شبیه به پارامترهای خروجی لیست حواله ها می باشد
